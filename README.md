# Arranger Manager

Органайзер аранжировок для проектов Fender Studio Pro. Основной продукт сейчас — отдельное Windows-приложение, которое читает **сохранённые** `.song` без запуска DAW. В репозитории также есть обычный Hub VST3 и экспериментальный ARA Inspector; ARA не требуется для работы приложения.

## Текущее состояние — 0.1

- Каталог нескольких `.song`: добавление проектов, папки, перемещение и удаление записей из каталога. Исходные файлы при этом не удаляются.
- Дерево `папка → песня → дорожка → аудио/MIDI-клип`; группы Tracks/Markers и треки раскрываются по запросу. Секции аранжировки из сохранённого проекта показаны у пересекающихся клипов как `[Название]` с кружком цвета секции. Цвет трека и его заметки также берутся из `.song`.
- Статус **клипа** читается из его имени: `WIP` или `WIP | заметка`. Поддерживаются `POOL`, `TODO`, `WIP`, `DRAFT`, `WAIT`, `DONE`, `BLOCKED`; старое `REVIEW` распознаётся как `WAIT`. Старые имена с `P1`–`P4` читаются, но приоритет клипа не отображается.
- Статусы **песни** и **трека** выбираются вручную и независимо в колонке Status. Пока они хранятся в каталоге приложения на этом компьютере, **не в `.song`**. Приоритет песни P1–P4 пока не реализован.
- PROG показывает число клипов со статусом `DONE` от **всех** клипов: у трека, песни и суммарно у папки. Клип без статуса считается незавершённым. Это счётчик клипов, а не покрытие времени или секций аранжировки.
- Info, Notes, заметки треков, дорожки, клипы, секции и маркеры читаются из сохранённого `.song`. Изменения в Studio Pro становятся видны после сохранения. Приложение пока не записывает в `.song` и не видит несохранённые изменения.

## Сборка и тесты

Требуются CMake 3.22+, C++20 и JUCE 9.0.2 (CMake получает его через FetchContent). Основная Windows CI: `.github/workflows/windows-build.yml`.

```sh
cmake -S . -B build
cmake --build build --config Release --target ArrangerManagerDesktop ArrangerManagerHub_VST3 ArrangementTagTests SongSnapshotTests SongCatalogTests --parallel 2
ctest --test-dir build -C Release --output-on-failure
```

CI создаёт архив `Arranger-Manager-0.1-Windows-App` с `Arranger Manager.exe` и инструкцией. ARA Inspector собирается отдельно с `-DARRANGER_BUILD_ARA_INSPECTOR=ON` и ARA SDK 2.3.0. Сборка и тесты 0.1 прошли в Windows Build #35; пользовательская проверка 0.1 на его проектах ещё не зафиксирована.

## Как читать документы

`docs/CONCEPT.md`, `docs/ROADMAP.md` и `docs/HANDOFF.md` описывают **текущий** путь развития. Файлы `docs/HUB-0.0*.md`, `docs/STAGE0-TEST.md`, `docs/MAP-PREVIEW-0.0b.md`, `docs/DOCK-TEST-0.0d.md` и `docs/CONTEXT-BRIDGE-*.md` фиксируют **исторические прототипы и проверки**; их ранние UI, приоритеты на клипах и служебные ARA-дорожки не следует переносить в новую разработку как действующие требования.

Задачи по этапам ведутся в GitHub Issues; код 0.1 находится в [PR #20](https://github.com/vladleng/Arranger-Manager/pull/20) поверх [PR #16](https://github.com/vladleng/Arranger-Manager/pull/16). Перед новой работой проверьте статус веток и PR: исторические сборки ещё могут жить в отдельных draft PR.
