## Завершённый гибридный этап — #29, #31 и #33

Основа — принятая 0.1 fix4. В итерации 0.1b пользователь создаёт, называет и меняет статусы задач песни и их чек-поинтов в приложении. При наличии чек-поинтов задача показывает PROG по их статусам DONE. PROG песни считает DONE среди размеченных треков и задач верхнего уровня; чек-поинты отдельно в песне не считаются. Данные задач хранятся в локальном каталоге, `.song` остаётся только для чтения. База 0.1b проверена пользователем. Fix1 выравнивает кружки, заменяет текст Type на иконки и добавляет локальные Notes для задач, чек-поинтов, треков и клипов. Итерация 0.1c (#31) редактирует Notes и имена прямо в строках, сохраняет порядок задач и чек-поинтов после перетаскивания и добавляет четыре локальных типа песни с иконками. Итерация 0.1d (#33) показывает папки треков с размеченными потомками, открывает меню у курсора и добавляет локальные Notes песни без изменения исходных Notes в шапке. Пользователь подтвердил работу всей цепочки 2026-09-29; issues #29, #31, #33 закрыты. Дополнения получают следующую букву; `fix` используется только для исправлений.

## Отложено — запись закрытого `.song`, #8

Эксперимент 0.1a с записью копии в закрытом PR #28 не прошёл host проверку и не входит в текущую сборку. Возвращаться к исследованию записи только по новому решению пользователя. Исторический план: исследовать запись **на копии закрытого проекта**. Сначала поменять одно имя `AudioEvent` и одно `MusicPart`, сохранить все прочие ZIP entries, проверить открытие и повторное сохранение в Studio Pro. Событие нельзя идентифицировать одним `clipID`: после split/copy значения повторяются. Нужны проверка неизменности исходного файла, резервная копия, временный архив, валидация ZIP/XML и отказ при неоднозначности. Только после успешной host проверки рассматривать запись в оригинал и расширение на Info/Notes/заметки. При открытом проекте правки остаются в самой DAW.
