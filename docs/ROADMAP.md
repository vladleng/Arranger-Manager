## Этап 3 — закрытый `.song`, #8

Промежуточные версии этого этапа называются **0.1a, 0.1b, …**, а принятый результат — **0.2**.

| Версия | Проверяемый результат |
| --- | --- |
| 0.1a | Изолированный инструмент правит одно имя `AudioEvent` или `MusicPart` в новом файле-копии. Он сохраняет прочие записи ZIP, сверяет содержимое, отказывает при неоднозначности и не трогает исходный `.song`. Проверка обеих типов клипов и повторного Save в Studio Pro обязательна. |
| 0.1b | Выбор конкретного клипа и подготовка нового имени из интерфейса приложения; сохранение только в отдельную копию с теми же проверками. |
| 0.1c и далее | Защита от открытого/изменённого исходного проекта, резервная копия, временный архив и атомарная замена оригинала после отдельной host проверки. Info/Notes/заметки дорожек — отдельные проверки полей. |
| 0.2 | Закрытый проект можно безопасно редактировать из приложения в утверждённом объёме; проверены audio/MIDI, восстановление и отказ при конфликте. |

Событие нельзя идентифицировать одним `clipID`: после split/copy значения повторяются. Для 0.1a используется дорожка, тип, исходное имя и временные атрибуты; точных совпадений должно быть ровно одно. Оригинал пока не записывается. [Инструкция 0.1a](STAGE3-0.1a.md).

## Этап 4 — формат `.show`, #19

Сначала получить обезличенный или тестовый `.show`, исследовать его контейнер и структуру. Определить связи Show → песни, порядок, названия, статусы/заметки и поведение при сохранении. Начать с чтения; отдельное решение о записи принимать только после проверки формата и теста на копии. Не предполагать, что `.show` совпадает с `.song`.
