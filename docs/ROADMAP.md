# Arranger Manager — развитие рабочего пространства

**План от 2026-10-02.** Пользователь расширил цель: собственное рабочее пространство по принципу Notion с задачами, страницами, планом дня, общим календарём, Timeline, аналитикой соцсетей и интеграцией с ChatGPT. DAW остаётся частью продукта. План: [#36](https://github.com/vladleng/Arranger-Manager/issues/36).

## Исходная версия и порядок работы

Принятая рабочая версия — **0.1d**, ветка `hybrid-0-1d-folders-menu-song-notes`, PR #34; текущий код ещё не слит в main. Реализованы read-only чтение .song, каталог песен, статусы/прогресс, папки треков, локальные задачи/чек-поинты, inline Notes/имена, drag порядка и типы песен. Windows Build #50 и пользовательская приёмка пройдены. Issues #29, #31, #33 закрыты.

Новые возможности пока **не реализованы**. Начало следующей разработки — **0.1e**, финал первого нового этапа — **0.2**. Далее этапы выпускают 0.3–0.7, а промежуточные дополнения получают буквы предыдущей версии: 0.2a, 0.2b → 0.3 и т.д. `fix` обозначает исправление. Указанные подэтапы — план разбиения; их можно уточнять по результатам прототипа, не объявляя будущие версии готовыми. Каждый финал требует проверки сборки и пользовательской приёмки. Этот запрос оформляет план и документы; код не изменяется.

Основной порядок: 1 → 2 → 3 → 4 → 5 → 6. Календарь и Timeline используют общую модель дат, выбранную в этапе 2. Аналитика технически зависит от ядра этапа 1; GPT для задач — от ядра и интеграционного слоя, для аналитики — от фактических данных этапа 5. До разработки интеграций нужны проверенные возможности сервисов. Функции выполняются по одному подэтапу с сохранением принятых данных и поведения DAW.

## Действующие ограничения и дополнительные ветки

- Чтение .song остаётся read-only. PROG песни учитывает DONE размеченных треков и её задач верхнего уровня; чек-поинты считаются только внутри задачи. Общие задачи других страниц в PROG песни не попадают.
- #7 — дальнейшие особенности каталога DAW. Общий поиск, экспорт/импорт, ID и переносимость теперь относятся к этапу 1; не делать второй несогласованный механизм.
- #19 — исследование .show, дополнительная DAW-ветка. Старое название «этап 4» историческое и не относится к этапу 4 нового плана. Нужен тестовый файл; формат не исследован.
- #8/#18 и writer PR #28 — запись .song отложена, эксперимент исключён из сборки.
- #35 — телефон и синхронизация устройств остаются отложенными; планировать ядро со стабильными ID, но не включать мобильную реализацию в 0.2–0.7 автоматически.
- Полная совместимость с Notion, импорт его баз, совместная работа нескольких людей, произвольные формулы/rollups, внешние календари, автопубликация, автоматическое перепланирование и автономные GPT-действия — возможные расширения после основного сценария, не текущие критерии.
- Анализ временного покрытия DAW, MIDI/CC, Track Agents, Harma Waves и ARA — отдельные исследования после конкретного задания.
