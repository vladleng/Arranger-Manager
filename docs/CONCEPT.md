# Arranger Manager — действующая концепция

**По состоянию на 0.1 fix1 (2026-09-28).** Это продуктовые решения и проверенные границы текущего Hub. Исторические эксперименты ARA и скриптового моста описаны в `STAGE0-TEST.md`, `CONTEXT-BRIDGE-PROBE.md` и версиях `HUB-0.0*.md`.

## Цель и модель

Показывать состояние нескольких музыкальных проектов и незавершённые части аранжировки на основе **сохранённых файлов Studio Pro**. Иерархия: папка каталога → песня (`.song`) → дорожка → обычный аудиоклип или MIDI-партия. Секции Arranger и маркеры читаются из того же проекта. Секции показываются у клипов как цветные `[Название]`, а не отдельными задачами.

Создание служебных дорожек и silent WAV не требуется. ARA Inspector остаётся прототипом для возможных будущих функций, если чтения сохранённого файла окажется недостаточно.

## Источники данных и редактирование

| Данные | Версия 0.1 fix1 | Направление |
| --- | --- | --- |
| Песня, дорожки, цвета, клипы, секции, маркеры, Info, Notes и заметки дорожек | Читаются из сохранённого `.song`; видны после Save в Studio Pro | Поддерживать изменения формата и проверять новые версии DAW |
| Статус клипа и текст задачи | Из имени события: `STATUS` или `STATUS | заметка` | Для закрытого проекта исследовать безопасную запись нативного имени в `.song` (#8) |
| Статус песни | Ручное значение в локальном каталоге приложения | Выяснить допустимый нативный носитель и безопасную миграцию; пока не обещать хранение в `.song` |
| Статус дорожки | Первая строка заметки дорожки в `.song`: `STATUS` или `STATUS | текст` | Меняется в Studio Pro; старые локальные статусы треков 0.1 не используются |
| Папки и пути к песням | Локальный каталог приложения | Продумать перенос/поиск путей и обработку пропавших файлов |
| Приоритет песни P1–P4 | Пока отсутствует | Реализовать только для песни; способ хранения выбрать отдельно (#7) |

В открытом проекте имена событий и заметки редактируются в Studio Pro. Приложение показывает последний сохранённый снимок, не несохранённые правки. Внешне изменять открытый `.song` нельзя: следующий Save в DAW может перезаписать изменения. Запись в закрытый проект — отдельный этап после проверки на копии в Studio Pro (#8).

## Статус и готовность

Статусы: `POOL`, `TODO`, `WIP`, `DRAFT`, `WAIT`, `DONE`, `BLOCKED`. Старое имя `REVIEW` читается как `WAIT`. Приоритеты `P1` красный, `P2` оранжевый, `P3` жёлтый, `P4` серый предназначены для песен, **ещё не реализованы**. Старые клипы с токеном `Pn` распознаются для совместимости, но в интерфейсе клипов его нет.

Статус песни не выводится из статусов треков: например песня `WAIT`, а один трек `WIP`. Статус трека не выводится из клипов. **PROG** трека и песни в 0.1 fix1 — `DONE / клипы с распознанным статусом`; обычные клипы без статуса исключены. **PROG папки** — `песни DONE / все песни в папке`; песня без статуса считается незавершённой. Статус трека не меняет PROG трека, а статус песни не меняет PROG песни.

Будущий анализ покрытия секций и gaps — отдельная метрика по временным интервалам. Её нельзя подменять текущим счётчиком клипов: длины событий, пересечения и рабочий диапазон потребуют отдельной модели и тестов.

## Долгосрочное развитие

- Поиск, переносимость каталога, обзор песен и приоритеты на уровне песни (#7).
- Безопасное редактирование **закрытого** `.song`, сначала имён отдельных audio/MIDI событий, после host проверки — Info/Notes/заметок (#8).
- Исследование `.show` как отдельного формата и сценария, без предположений об идентичности его структуры с `.song` (#19).
- В более поздних этапах — анализ временного покрытия и пробелов, задачи с привязкой к секции/позиции, история сессий, опциональные Track Agents и связь с Harma Waves. Эти функции пока не реализованы.

Текущая архитектура и порядок работы описаны в [HANDOFF](HANDOFF.md) и [ROADMAP](ROADMAP.md). GitHub Issues содержат конкретные проверяемые задачи; этот документ хранит принципы, а старые прототипы остаются историей исследований.
