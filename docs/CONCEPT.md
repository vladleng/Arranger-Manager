# Arranger Manager — действующая концепция

**Решение 2026-09-29.** Основа — принятая 0.1 fix4. Далее задачи и чек-поинты хранятся локально; проект Studio Pro приложение не записывает. Исторические эксперименты ARA и скриптового моста описаны в `STAGE0-TEST.md`, `CONTEXT-BRIDGE-PROBE.md` и версиях `HUB-0.0*.md`.

## Цель и модель

Показывать состояние нескольких музыкальных проектов и незавершённые части аранжировки на основе **сохранённых файлов Studio Pro**. Иерархия: папка каталога → песня (`.song`) → папка дорожек (если есть) → дорожка → обычный аудиоклип или MIDI-партия в пределах Start/End. Папки дорожек могут быть вложены и выводятся только при наличии размеченного трека внутри. Секции Arranger и маркеры читаются из того же проекта. Секции показываются у клипов компактными цветными квадратами в Parts; маркеры в дереве скрыты и не служат источником Notes клипов.

Создание служебных дорожек и silent WAV не требуется. ARA Inspector остаётся прототипом для возможных будущих функций, если чтения сохранённого файла окажется недостаточно.

Приложение показывает последний сохранённый снимок, не несохранённые правки. Внешне изменять открытый `.song` нельзя: следующий Save в DAW может перезаписать изменения. Запись в закрытый проект отложена (#8).

## Задачи и локальные заметки

В локальном каталоге каждой песни принадлежат именованные задачи. Каждая задача может содержать именованные чек-поинты. Их имена редактируются двойным кликом, порядок меняется перетаскиванием среди соседних элементов того же уровня. Их статусы меняются вручную из того же набора, что статус песни. Когда у задачи есть чек-поинты, она показывает `DONE / всего`. PROG песни суммирует размеченные треки Studio Pro и задачи верхнего уровня: только DONE увеличивает числитель. Чек-поинты не добавляются в PROG песни повторно; завершение всех чек-поинтов автоматически не меняет статус задачи. Удаление песни из каталога удаляет её локальные задачи и заметки, но не файл `.song`. У задач, чек-поинтов и треков Notes привязаны к ID; у клипов — к дорожке, типу, clipID, позиции и длине с порядковым номером при полном совпадении. Изменение позиции или длины клипа может потребовать новой заметки. Кружки задач и треков выровнены, чек-поинты отмечены точкой, Type использует только иконки.

## Статус и готовность

Статусы: `POOL`, `TODO`, `WIP`, `DRAFT`, `WAIT`, `DONE`, `BLOCKED`. Старое имя `REVIEW` читается как `WAIT`. Приоритеты `P1` красный, `P2` оранжевый, `P3` жёлтый, `P4` серый предназначены для песен, **ещё не реализованы**. Старые клипы с токеном `Pn` распознаются для совместимости, но в интерфейсе клипов его нет.

Статус песни не выводится из статусов треков: например песня `WAIT`, а один трек `WIP`. Статус трека не выводится из клипов, но его наличие определяет, включается ли трек в обзор. **PROG трека** — `клипы DONE / клипы с распознанным статусом`; обычные клипы исключены. **PROG песни** — `треки и задачи DONE / все размеченные треки и задачи`, независимо от клипов. **PROG папки** — `песни DONE / все песни в папке`; песня без статуса считается незавершённой. Ручной статус песни не меняет её PROG.

Будущий анализ покрытия секций и gaps — отдельная метрика по временным интервалам. Её нельзя подменять текущим счётчиком клипов: длины событий, пересечения и рабочий диапазон потребуют отдельной модели и тестов.

## Долгосрочное развитие

- Поиск, переносимость каталога, обзор песен и приоритеты на уровне песни (#7).
- Исследование записи `.song` (#8) отложено до отдельного решения пользователя.
- Исследование `.show` как отдельного формата и сценария, без предположений об идентичности его структуры с `.song` (#19).
- В более поздних этапах — анализ временного покрытия и пробелов, задачи с привязкой к секции/позиции, история сессий, опциональные Track Agents и связь с Harma Waves. Эти функции пока не реализованы.

Текущая архитектура и порядок работы описаны в [HANDOFF](HANDOFF.md) и [ROADMAP](ROADMAP.md). GitHub Issues содержат конкретные проверяемые задачи; этот документ хранит принципы, а старые прототипы остаются историей исследований.
