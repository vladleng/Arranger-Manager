# Arranger Manager — действующая концепция

**Новое направление от 2026-10-02.** Arranger Manager развивается в собственное рабочее пространство по принципу Notion: страницы и задачи, план дня, общий календарь, Timeline, аналитика соцсетей и интеграция с ChatGPT. DAW — действующий модуль этого пространства. Название пока сохраняется, переименование пользователь не задал.

**Реализовано:** принятая 0.1d на основе 0.1 fix4 — Windows-приложение с каталогом DAW и локальными задачами. **Запланировано:** общее рабочее пространство в 0.2 и следующие этапы до 0.7. Новые функции ещё не написаны. Подробные подэтапы и критерии: [ROADMAP](ROADMAP.md), общий план #36, этапы #37–#42.

## Цель и общая модель

Пользователь создаёт именованные страницы для проектов, музыки, контента и обычных дел. На странице есть описание и задачи; задача открывается как подробная страница с текстом и чек-поинтами. Общий список содержит задачи всех страниц. Из него формируется план выбранного дня. Общий календарь и Timeline используют те же записи и даты, не создавая копии задач.

Календарь показывает задачи и события всех страниц, с фильтром источника. Timeline — план работ по календарным датам, с интервалами, вехами и последовательностью. Плановые даты, дедлайн и фактическое завершение — разные значения. При изменении статуса или даты исходной задачи все представления обновляются.

Аналитика получает проверенные метрики аккаунтов/публикаций и связывает их со страницами контента. ChatGPT помогает планировать, разбивать работу на задачи и анализировать выбранный контекст. Встроенный помощник через API и доступ ChatGPT к приложению через MCP — два возможных направления; основной путь ещё предстоит выбрать. Система хранит факты отдельно от рекомендаций модели.

Это собственный продукт с возможностями страниц и представлений, а не обещание полного набора всех функций Notion. В первом этапе редактор содержит текст, заголовки, списки, чек-листы и ссылки; подробные базы с произвольными формулами, импорт Notion и совместная работа относятся к будущим расширениям. Локальное ядро работает без сети, соцсети и GPT подключаются отдельно. Техническая модель и нерешённые вопросы: [WORKSPACE-ARCHITECTURE](WORKSPACE-ARCHITECTURE.md).

## Модуль DAW и совместимость с 0.1d

Сохранять состояние нескольких музыкальных проектов на основе **сохранённых файлов Studio Pro**. Иерархия: папка каталога → песня (.song) → папка дорожек (если есть) → дорожка → аудиоклип или MIDI-партия в пределах Start/End. Вложенные папки дорожек показываются при наличии размеченных треков. Секции Arranger представлены цветными квадратами Parts, маркеры остаются в Studio Pro и не служат источником Notes клипов.

Задачи песни должны стать частью общей модели со своими прежними ID; открытие их в списке, Сегодня или календаре не создаёт новых задач. Обычные задачи других страниц не добавляются в PROG песни. Источники статусов треков/клипов, правила прогресса и локальные Notes сохраняются при миграции. Путь .song станет атрибутом устойчивой записи песни, а не единственным идентификатором.

Приложение продолжает только читать .song. Создание служебных дорожек и silent WAV не требуется. ARA остаётся исследовательским прототипом, а не основой нового рабочего пространства. Рабочее DAW-поведение ниже описывает именно текущую 0.1d, до реализации общих страниц.

Без статуса дорожка не выводится и не учитывается в PROG песни. Приложение показывает последний сохранённый снимок, не несохранённые правки. Внешне изменять открытый `.song` нельзя: следующий Save в DAW может перезаписать изменения. Запись в закрытый проект отложена (#8).

## Задачи и локальные заметки

В локальном каталоге каждой песни принадлежат именованные задачи. Каждая задача может содержать именованные чек-поинты. Их имена редактируются двойным кликом, порядок меняется перетаскиванием среди соседних элементов того же уровня. Их статусы меняются вручную из того же набора, что статус песни. Когда у задачи есть чек-поинты, она показывает `DONE / всего`. PROG песни суммирует размеченные треки Studio Pro и задачи верхнего уровня: только DONE увеличивает числитель. Чек-поинты не добавляются в PROG песни повторно; завершение всех чек-поинтов автоматически не меняет статус задачи. Удаление песни из каталога удаляет её локальные задачи и заметки, но не файл `.song`. У задач, чек-поинтов и треков Notes привязаны к ID; у клипов — к дорожке, типу, clipID, позиции и длине с порядковым номером при полном совпадении. Изменение позиции или длины клипа может потребовать новой заметки. Кружки задач и треков выровнены, чек-поинты отмечены точкой, Type использует только иконки.

## Статус и готовность

Статусы: `POOL`, `TODO`, `WIP`, `DRAFT`, `WAIT`, `DONE`, `BLOCKED`. Старое имя `REVIEW` читается как `WAIT`. Приоритеты `P1` красный, `P2` оранжевый, `P3` жёлтый, `P4` серый предназначены для песен, **ещё не реализованы**. Старые клипы с токеном `Pn` распознаются для совместимости, но в интерфейсе клипов его нет.

Статус песни не выводится из статусов треков: например песня `WAIT`, а один трек `WIP`. Статус трека не выводится из клипов, но его наличие определяет, включается ли трек в обзор. **PROG трека** — `клипы DONE / клипы с распознанным статусом`; обычные клипы исключены. **PROG песни** — `треки и задачи DONE / все размеченные треки и задачи`, независимо от клипов. **PROG папки** — `песни DONE / все песни в папке`; песня без статуса считается незавершённой. Ручной статус песни не меняет её PROG.

Будущий анализ покрытия секций и gaps — отдельная метрика по временным интервалам. Её нельзя подменять текущим счётчиком клипов: длины событий, пересечения и рабочий диапазон потребуют отдельной модели и тестов.

Релизы и разбиение — план на основании нового задания, а не утверждение выполненной разработки. Следующий подэтап для реализации — 0.1e; этот запрос оформляет документацию и issues. Каждую реализацию завершать сборкой и пользовательской приёмкой.
