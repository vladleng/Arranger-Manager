# Arranger Manager 0.1f — навигация и страницы

База: 0.1e принята 2026-10-02, PR #43 слит в main, Build #59 успешна.
0.1f — кандидат следующего подэтапа #37; Windows CI и пользовательская приёмка отслеживаются в PR.

## Работа с приложением

Слева — разделы DAW, Все задачи, обычные страницы с вложенностью и Архив.
Последний открытый раздел/страница сохраняется в настройках; при отсутствующей или архивной странице приложение открывает DAW.

- **+ Страница** создаёт обычную страницу верхнего уровня.
- Выбрать страницу → **+ Вложенная** создаёт дочернюю.
- **Переименовать** или двойной клик по странице меняет её заголовок; ID и содержимое сохраняются.
- **Переместить** позволяет выбрать активного родителя или верхний уровень. Сама страница и её потомки исключены из списка родителей; команда также проверяет циклы.
- **В архив** скрывает страницу вместе с потомками, сохраняя содержимое и связи.
- **Архив** → выбрать страницу → **Восстановить**. Отдельно архивированный ребёнок остаётся архивированным после восстановления родителя; сначала восстановить родителя, затем ребёнка.
- Правый клик по странице открывает те же команды у курсора.

Обычные страницы на этом подэтапе показывают заголовок, путь вложенности и сохранённые блоки для чтения. Минимальный редактор блоков — следующий 0.1g; новые общие задачи — 0.1h. Прототип 0.1e доступен через Workspace → Editor prototype. Его архивированную страницу нужно восстановить перед редактированием.

**DAW** содержит привычный каталог песен и редакторы задач/Notes.
**Все задачи** собирает существующие задачи песен: статус, имя и страница-источник. Двойной клик или «Открыть песню» переключает в DAW, раскрывает папку/песню и выделяет источник. Это ссылки на прежние ID, отдельные копии задач не создаются. Чек-поинты остаются внутри задачи.

Песни и папки каталога управляются в DAW; команды обычных страниц не переименовывают и не архивируют эти записи. Это сохраняет разделение до DAW-интеграции страниц в 0.1i.

## Приёмка

1. Запустить пакет Arranger-Manager-0.1f-Windows-App. Проверить прежний каталог, Notes и PROG в DAW.
2. Создать страницу «Контент», вложенную «YouTube» и ещё один уровень «Shorts». Проверить дерево и строку пути.
3. Переименовать «YouTube» в «Видео». Переместить её под другую страницу и затем на верхний уровень: «Shorts» должен остаться её ребёнком.
4. В «Переместить» убедиться, что родителем нельзя выбрать саму страницу и её потомков. Пустое имя не должно сохраняться.
5. Архивировать родительскую страницу; всё поддерево исчезает из активного списка. Восстановить в Архиве: прежние имена и вложенность возвращаются.
6. Закрыть/открыть приложение: страницы, порядок, вложенность и выбранный раздел сохраняются.
7. В «Все задачи» открыть задачу из каждой из двух песен; перейти в DAW, изменить статус/имя, вернуться — обновления должны быть видны без дублей.
8. На странице Editor prototype проверить показ ранее сохранённых блоков; архивировать её и восстановить — содержимое сохраняется.

Хранилище остаётся workspace schema 1 / catalog schema 2. Новая миграция не нужна.
Сохранение обычных страниц проходит через WorkspaceController: неудачная команда/запись не меняет живую модель.
Резервные копии и восстановление всего пространства — как в HYBRID-0.1e.md.

## Код и проверки

WorkspaceCommands — правила изменений, WorkspaceQueries — дерево/архив/ссылки задач,
WorkspaceController — применение с проверкой и сохранением; WorkspaceShell — UI.
SongSnapshot остаётся отдельным read-only адаптером DAW.

WorkspaceNavigationTests проверяет дерево, циклы, архив/восстановление, ID/блоки,
источники задач, перезапуск и откат команды при отказе записи. Предыдущие четыре набора также выполняются.
