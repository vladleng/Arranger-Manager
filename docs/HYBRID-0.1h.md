# Arranger Manager 0.1h — общие задачи и страницы задач

База — принятая 0.1g, PR #45 в main, Windows Build #67 (6/6 tests).
0.1h — кандидат подэтапа #37; Windows CI и пользовательская приёмка — в PR.

## Работа с задачами

1. Открыть обычную страницу. **Блоки** содержит прежний редактор; **Задачи (N)** — таблицу задач этой страницы. **Все задачи** показывает общие задачи и ссылки на задачи песен.
2. Правый клик по шапке таблицы, пустому месту или строке → **Создать задачу**. Указать название и страницу-владельца; на странице владелец выбран заранее.
3. Стрелка слева раскрывает задачу: её Notes и активные чек-поинты. Стрелка у чек-поинта раскрывает его Notes. Повторный клик сворачивает строку. Выбор и раскрытие сохраняются при обновлении; записи различаются по ID.
4. Таблица использует тёмный фон, линии вложенности, цветные статусы, P1–P4 и полосы прогресса. Прогресс задачи — DONE / активные чек-поинты; у чек-поинта 100% означает DONE. Его статус не меняет статус задачи.
5. Правый клик по задаче → **Открыть задачу**, **Переименовать / свойства / Notes**, **Статус**, **Приоритет**, **Добавить чек-поинт**, **Восстановить чек-поинт**, **Архивировать**. Восстановление появляется при наличии архивных чек-поинтов. У чек-поинта — изменение названия/Notes, статус и архивирование. Отдельных кнопок этих действий в таблице нет.
6. **Открыть задачу** или двойной клик открывает полный экран той же записи: название, статус, приоритет, многострочные Notes, раскрывающаяся таблица чек-поинтов и **тот же блочный редактор 0.1g** для описания. Чек-поинты находятся над описанием. Правый клик по шапке их таблицы открывает действия задачи.
7. Свойства сохраняются после 700 мс паузы; описание — после 500 мс. Правый клик по надписи **Свойства задачи** открывает **Сохранить**, **Перечитать свойства**, **К странице**, **Архивировать задачу**. Ввод сохраняется до меню, перехода и закрытия; отказ записи блокирует действие. История блочного редактора меняет только описание.
8. Архивирование сохраняет ID, свойства, описание и чек-поинты. В общем **Архиве** выбрать задачу → **Восстановить**. При архивном владельце сначала восстановить страницу. Необратимого удаления здесь нет. Действия страницы доступны по правому клику в боковой панели.

Статус задачи выбирается вручную. Выполнение чек-поинта или текстового чек-листа не меняет статус автоматически; счётчик чек-поинтов показывает DONE среди активных записей.

Задачи песен в **Все задачи** остаются ссылками на DAW-каталог и открывают песню. Их текущие ID, Notes и PROG сохранены. Подробные песенные страницы и их связь с DAW — 0.1i.

## Миграция и восстановление

Workspace schema **2** / catalog schema **2**. При первом запуске с workspace schema 1:
- документ полностью проверяется;
- точный исходник (включая исходные байты кодировки/окончаний строк) сохраняется в **Arranger Manager.workspace.json.schema-1.json** (при другом сохранённом исходнике используется имя с UUID);
- schema 2 записывается через проверенный временный файл; исходник также остаётся в обычной .backup до следующих записей.

Миграция не меняет ID/вложенность/блоки страниц, ID песен/задач/чек-поинтов, Notes keys и порядок. Повторный запуск не повторяет миграцию. Старые версии 0.1e–0.1g не открывают schema 2, поэтому не могут молча потерять новые задачи. Восстановление предыдущего workspace — прежнее меню Workspace / CLI; legacy-v1 backup настроек сохранена.

При ошибке записи живые данные не заменяются, черновик остаётся в полях, переход/закрытие блокируются. Для явного отказа от свойств — пункт **Перечитать свойства** с подтверждением; для описания — его собственная кнопка Перечитать. При изменении файла извне новые данные загружаются после перезапуска.

## Приёмка

1. Запустить новый пакет с прежними данными 0.1g. Проверить страницы, их блоки, каталог DAW, Notes и PROG. В Workspace → Storage information проверить Schema 2; рядом с workspace есть schema-1.json.
2. На двух обычных страницах создать по задаче. Проверить счётчики, отдельные списки и общий Все задачи без дублей. Создать задачу также через Все задачи с выбором владельца.
3. В задаче изменить название, статус, P1–P4 и Notes. Перейти на страницу и в Все задачи: изменения видны; оба списка открывают ту же запись.
4. Через правый клик добавить несколько чек-поинтов, изменить статус/Notes. Архивировать чек-поинт и вернуть. Счётчик меняется, статус задачи сохраняется.
5. Создать подробное описание из пяти типов блоков. Проверить отмену/повтор и порядок. Отмена описания не должна откатывать Notes, статус или чек-поинты.
6. Ввести Notes и текст описания, сразу перейти на другую задачу/DAW или закрыть окно. После перезапуска весь ввод сохранён; последний открытый список/задача восстановлен.
7. Удалить задачу в архив → восстановить. Проверить все свойства, блоки и чек-поинты. Отдельно архивировать задачу, затем её родительскую страницу; после восстановления страницы задача остаётся в архиве.
8. Архивировать страницу с вложенной страницей и задачами: все её задачи исчезают из Все задачи. Восстановить страницу: активные задачи возвращаются без дублей.
9. Проверить песенные задачи из Все задачи: открывается прежний DAW-каталог, Notes/PROG работают как раньше.

## Код и проверки

WorkspaceTask — одна запись с ownerPageId; представления хранят ссылки, не копии. TaskDetails использует WorkspaceCommands/Controller; описание связывается с BlockEditor через callbacks task ID. Архивы страниц/задач/чек-поинтов сохраняют ссылки и ID. Доменная проверка запрещает отсутствующего/DAW владельца, повторные ID, неизвестные статусы/приоритеты и изменения архивных объектов.

GeneralTaskTests проверяет schema 1 → 2 с точной копией/повторным запуском/ошибкой резервирования, свойства/ссылки/владельцев, описание и историю, независимость DAW, чек-поинты, наследование архива и восстановление, отказ записи и повреждённую schema 2. Предыдущие шесть наборов также выполняются. CI сначала выполняет тесты, затем собирает Desktop/Hub.


## Проверка раскрывающейся таблицы

- Раскрыть задачу и два чек-поинта; свернуть и раскрыть задачу снова. Notes, вложенность и раскрытие чек-поинтов сохраняются.
- Правым кликом изменить статус/приоритет/название нужной строки. Одноимённые задачи и чек-поинты меняются независимо.
- Архивировать раскрытый чек-поинт: строка и Notes исчезают, прогресс пересчитывается. Восстановить его из меню задачи: ID и Notes сохранены.
- Создать первую задачу правым кликом в пустой таблице. Проверить меню в **Все задачи**, **Задачи** страницы и в подробном экране.
- Проверить таблицу при минимальном размере окна. Описание и чек-поинты в подробном экране прокручиваются независимо.

`GeneralTaskTests` дополнен проверками структуры дерева, архивов, владельца и отсутствия изменений данных при раскрытии. `TaskTreeUiTests` проверяет реальные клики по стрелкам, выбор/раскрытие после обновления, открытие исходной записи, архив/восстановление, блокировку меню при отказе сохранения и рендер таблицы в PNG. Снимок `task-tree-preview.png` включён в Windows-пакет.
