# Arranger Manager 0.1e — модель и хранилище

Версия для проверки подэтапа #37: постоянные ID и миграция данных из 0.1d.
Статус: кандидат; после успешного Windows CI нужна пользовательская приёмка.

## Запуск

Распаковать Arranger-Manager-0.1e-Windows-App, запустить Arranger Manager.exe.
Настройки окна/выбранного проекта остаются прежними. При первом запуске каталог переносится в
Arranger Manager.workspace.json рядом с прежним .settings в пользовательской папке Moon River Studio.

Исходный songCatalog в .settings остаётся сохранённым на момент перехода. Начиная с 0.1e он больше не обновляется: запуск 0.1d покажет старое состояние, а не изменения новой версии. Поэтому для актуальных задач использовать 0.1e.

Workspace → Storage information показывает путь к документу, UUID пространства, revision и резервные файлы:
- .legacy-v1.json — точный исходный JSON каталога 0.1d; не обновляется.
- .backup — предыдущая успешно сохранённая версия рабочего пространства.
- .before-restore-UUID.json — сохранённый текущий файл перед восстановлением.

## Что проверить

1. Открыть свой существующий каталог. Проверить папки, песни, их статусы/типы, порядок задач и чек-поинтов, все Notes. PROG должен совпадать с 0.1d.
2. Ввести заметку с кириллицей, изменить статус задачи и порядок. Закрыть приложение, запустить снова. Проверить данные; Workspace ID должен остаться прежним.
3. Добавить ещё одну песню/папку и задачу. Перезапустить; дубликаты не должны появиться. Исходные .song только читаются.
4. Workspace → Editor prototype: добавить Text, Heading, List, Checklist и Link. Ввести текст/URL, отметить чекбокс; выбрать блок кнопкой Select, изменить порядок Move up/down; проверить Undo/Redo. Закрыть окно и приложение; открыть прототип снова — блоки и их ID/порядок должны сохраниться.
5. Для сравнения можно открыть editor-web.html из пакета в браузере. Это отдельный пример, не работающий с каталогом.
6. Проверка восстановления на тестовых данных: изменить заметку дважды, чтобы .backup содержал первое изменение. Workspace → Restore previous workspace backup → Restore должен вернуть предыдущую версию и сохранить текущий файл отдельно. Cancel не меняет ничего.

При повреждённом документе приложение покажет ошибку и не заменит файл пустым каталогом. Для восстановления .backup при закрытом приложении запустить из PowerShell в папке exe:

```powershell
& '.\Arranger Manager.exe' --restore-workspace-backup
```

Первый запуск, резервирование и запись могут остановиться с явной ошибкой, если каталог некорректен или папка недоступна для записи. На большом каталоге запись всего документа выполняется синхронно; оптимизация по фактическому объёму — отдельная работа. Не проверять повреждение на единственной копии своих данных.

## Границы

0.1e создаёт фундамент и проверочный редактор. Боковая панель страниц — 0.1f, полноценный минимальный редактор — 0.1g, общие задачи — 0.1h. Календарь, Timeline, аналитика, GPT и телефон пока не реализованы. Повторное связывание файла проверяется в модели/тестах; пользовательский интерфейс — 0.1i.

Техническое сравнение и выбор: WORKSPACE-0.1e-DECISIONS.md.
