## Текущее поведение 0.1d

| Объект | Источник и редактирование | Прогресс и отображение |
| --- | --- | --- |
| Клип | Статус/имя из `STATUS \| название \| заметка` в `.song`; Notes строки локальное | Только клипы целиком в Start/End; Type — иконка, Parts — квадраты секций. Третья часть имени не выводится в локальном Notes |
| Трек | Статус из начала имени в `.song`, цвет и тип оттуда же; Notes локальное | Только треки с распознанным статусом; PROG = клипы DONE / размеченные клипы |
| Папка треков Studio Pro | `FolderTrack`, `parentFolder`, исходный порядок | Вложенное дерево, только папки с размеченными потомками; без собственного статуса и вклада в PROG |
| Задача | Локальные имя, статус, Notes, порядок; имя — двойной клик, порядок — drag | При чек-поинтах PROG = чек-поинты DONE / все чек-поинты; статус задачи меняется вручную |
| Чек-поинт | Локальные имя, статус, Notes, порядок внутри своей задачи | Не считается в PROG песни повторно; DONE всех чек-поинтов не меняет статус задачи автоматически |
| Песня | Структура, Info и Notes шапки из `.song`; Status, Type и Notes строки локальные | PROG = треки и задачи DONE / все размеченные треки и задачи верхнего уровня |
| Папка каталога | Локальная группировка песен | PROG = песни со статусом DONE / все песни в папке |

Статусы `POOL`, `TODO`, `WIP`, `DRAFT`, `WAIT`, `DONE`, `BLOCKED`; исторический REVIEW читается как WAIT. Только DONE увеличивает прогресс. Ручные статусы, Type песни и PROG независимы. Типы песни: начало — красный круг, рыба — жёлтая рыбка, сведение — синий микшер, готовый микс — зелёный Play в круге; возможен пустой тип. Приоритет песни пока отсутствует; старые P1–P4 клипов игнорируются UI.

Notes редактируются прямо в ячейке: выход сохраняет, Esc отменяет; меню сохраняет альтернативный редактор. Переименование задач/чек-поинтов — двойной клик; Enter сохраняет, Esc отменяет. Drag меняет порядок задач только в одной песне, чек-поинтов — только внутри одной задачи. Меню открываются у экранной точки клика. Задачи и треки имеют выровненные кружки, чек-поинты — точку, Type содержит только иконки.

Обновление снимка проверяется по времени изменения и размеру файла примерно раз в секунду. Изменения DAW видны после Save. Это не live состояние DAW и не полноценное обнаружение смены содержимого при одинаковых времени и размере. Отсутствующий проект остаётся в каталоге с ошибкой чтения. Маркеры остаются в Studio Pro; в дереве не выводятся, Start/End используются для фильтрации клипов.

## Локальные данные

Настольное приложение хранит JSON каталога `version: 1` в JUCE `ApplicationProperties`, ключ `songCatalog`; выбранный путь — `lastProjectPath`. Параметры файла настроек задаются в `HubApplication.cpp`: applicationName `Arranger Manager`, folderName `Moon River Studio`, suffix `.settings`. Каталог включает папки, пути песен, ручные статусы и типы, задачи/чек-поинты и локальные заметки. Обновление exe не должно сбрасывать эти настройки. Удаление записи песни удаляет её локальные данные, но сохраняет исходный `.song`.

Песня идентифицируется путём на компьютере, собственного устойчивого UUID песни пока нет. У задач и чек-поинтов есть ID. `SongNoteKeys.h` связывает Notes песни с ключом `song`, задач/чек-поинтов с ID, треков с trackID; ключ клипа включает trackID, тип, clipID, позицию, длину, timeFormat и номер совпадающего события. После перемещения/изменения длины клипа заметка может перестать сопоставляться. Экспорт/импорт каталога и синхронизация пока отсутствуют.

## Новое в 0.1b

Задачи и чек-поинты живут внутри записи песни в JSON каталога `version: 1`; старые каталоги читаются без миграции. Контекстное меню песни создаёт задачу, меню задачи — чек-поинт, переименование и удаление; Status меняется кликом. Прогресс задачи виден только при наличии чек-поинтов. PROG песни считает DONE среди задач верхнего уровня и размеченных треков; завершённые чек-поинты не меняют статус задачи автоматически. Ветка основана на 0.1 fix4, экспериментальный writer не входит в сборку.

## Fix1: локальные заметки и UI

Notes строк задач, чек-поинтов, треков и клипов теперь локальные, хранятся в каталоге песни. Нативные track notes и третья часть имени клипа больше не выводятся в колонке; Info и Notes самой песни в шапке по-прежнему читаются из `.song`. Клик по Notes открывает редактор; пустая строка удаляет заметку. `SongNoteKeys.h` строит ключ из ID задачи/чек-поинта, trackID или набора trackID + тип + clipID + позиция/длина/timeFormat + номер совпадающего события. После перемещения/изменения длины клипа заметка может перестать сопоставляться. Кружки задач и треков выровнены, чек-поинты имеют точку слева, Type содержит только иконки.

## Дополнение 0.1c

Клик по Notes начинает редактирование в ячейке; выход из поля сохраняет, Esc отменяет. Двойной клик по имени задачи/чек-поинта редактирует его в строке. Перетаскивание задачи на соседнюю задачу той же песни или чек-поинта в пределах его задачи сохраняет новый порядок в JSON без смены ID, статусов и заметок. Type песни — локальный enum с четырьмя значками; старые каталоги получают пустой тип, Status и PROG не меняются. См. [инструкцию 0.1c](HYBRID-0.1c.md). Новые функции версионируются буквой; `fix` обозначает исправление.

## Дополнение 0.1d

Reader сохраняет `FolderTrack` и `parentFolder` из плоского списка Tracks в `.song` и порядок папок/треков. UI строит вложенную иерархию, скрывая папки без размеченных потомков. PROG песни считает треки как прежде. Контекстные меню и выбор Status/Type привязаны к экранной точке нажатия. Локальная заметка строки песни имеет ключ `song` в каталоге, исходные Notes `.song` остаются в шапке. См. [инструкцию 0.1d](HYBRID-0.1d.md).

## Код и границы

- `src/SongSnapshot.cpp/.h`: read-only ZIP/XML reader и фильтр клипов по Start/End для `metainfo.xml`, `notes.txt`, `notepad.xml`, `Song/song.xml`. Читает `MediaTrack`, `FolderTrack`/`parentFolder`, обычные `AudioEvent` и `MusicPart`, `ArrangerTrack` и `MarkerTrack`. Нормализует unbound `x:id` только при чтении. XML схемы тестировались на Studio Pro 8.1.2; другие версии требуют проверки.
- `src/ArrangementTag.h`: разбор `STATUS | название | заметка` и префикса имени трека, совместимость REVIEW/старого Pn. `src/SongProgress.h`: PROG трека по размеченным клипам, PROG песни по статусам отмеченных треков и локальных задач. `src/StudioProColour.h`: конвертация сохранённого цвета Studio Pro из ABGR для JUCE.
- `src/SongCatalog.h`: локальный каталог (`version: 1` JSON), папки, песни и ручной статус песни по пути. Старый 0.0m и 0.1 JSON читается; историческое поле `trackStatuses` игнорируется и не сохраняется заново. Удаление песни из каталога не удаляет исходный `.song`. `folderProgress` считает DONE песни среди всех песен папки.
- `src/HubEditor.cpp/.h`: общий JUCE UI для настольного приложения и Hub VST3; настольная версия получает каталог, VST3 работает как просмотр одного проекта. Здесь находятся PROG, цветные кружки, дерево и обновление снимков.
- `src/HubApplication.cpp`: Windows окно, сохранение каталога и выбранного проекта через `ApplicationProperties` в пользовательских настройках Moon River Studio.
- `src/HubProcessor.cpp`: обычный VST3 Hub. ARA исследование в `src/PluginProcessor.cpp`, `InspectorDocumentController.*`; по умолчанию ARA target выключен.
- `tools/read_song_metadata.py`, `tools/read_song_inventory.py`, `scripts/`: диагностические средства, не реализация записи `.song`.

Есть ограничения текущего reader: временные атрибуты берутся как сырые значения, сопоставление клипа с секцией опирается на эти значения; нестандартные takes/layers и другие версии файла не подтверждены. Совпадающий `clipID` после split/copy нельзя использовать как уникальный ключ для будущей записи. В 0.1d нет записи в `.song`, импорта `.show`, приоритета песен, поиска и анализа coverage/gaps. Если Start/End отсутствуют, дублируются или образуют неверный диапазон, клипы скрыты с предупреждением. 0.1d принята пользователем на его проектах; отдельное покрытие всех вариантов Scratch Pad, timeFormat и takes/layers не установлено. Не выдавать общую приёмку за проверку всех форматов.

## Сборка и проверки

```sh
cmake -S . -B build
cmake --build build --config Release --target ArrangerManagerDesktop ArrangerManagerHub_VST3 ArrangementTagTests SongSnapshotTests SongCatalogTests --parallel 2
ctest --test-dir build -C Release --output-on-failure
```

CMake 3.22+, C++20, JUCE 9.0.2 через FetchContent. `.github/workflows/windows-build.yml` пакует `.exe` и `docs/HYBRID-0.1d.md` под именем 0.1d. Windows Build #50 и пользовательская проверка 0.1d пройдены; предыдущие 0.1b и fix1/0.1c также подтверждены пользователем.
