# Arranger Manager 0.1g — блочный редактор страниц

База — принятая 0.1f, PR #44 в main, Windows Build #62, 5/5 tests.
0.1g — кандидат подэтапа #37. Windows CI и пользовательская приёмка отслеживаются в PR.

## Работа с редактором

Открыть обычную страницу в боковой панели. Слева в редакторе — блоки в порядке документа; справа — поля выбранного блока.

- Выбрать тип в верхнем списке → **+ Блок**. Блок добавляется после выбранного, в пустом документе — первым.
- **Имя блока** — необязательное имя для навигации. У каждого блока постоянный ID.
- Типы: **Текст**, **Заголовок**, **Список**, **Чек-лист**, **Ссылка**. Текст многострочный; список — один блок с произвольным числом строк. При смене типа ID, текст и другие поля сохраняются.
- Чек-лист: **Отмечено** меняет только отметку блока. Статус задач и PROG остаются прежними.
- Ссылка: текст/подпись и отдельный URL. **Открыть** запускает http/https ссылку в браузере по явному нажатию.
- **Выше / Ниже** переставляют выбранный блок; **Удалить** удаляет его с возможностью отмены.
- **Отмена / Повтор** действуют на содержимое текущей страницы: текст, имя, тип, отметку, URL, добавление, удаление и порядок. Ctrl+Z / Ctrl+Y, Ctrl+Shift+Z — те же действия; Ctrl+S — сохранить.
- Автосохранение после 500 мс паузы. Переключение страницы/раздела, команды страниц и закрытие окна сначала сохраняют ввод. Строка снизу показывает результат; **Сохранить** повторяет запись вручную.
- Если запись не удалась, ввод остаётся в редакторе, переход/закрытие блокируются. **Перечитать** с подтверждением отбрасывает несохранённый ввод и перечитывает блоки из текущей модели. Если сам файл изменён извне, для загрузки новой версии перезапустить приложение после явного отказа от черновика.
- История хранится в памяти отдельно для каждой страницы (до 100 успешных групп изменений), сохраняется при переходах в рамках одного запуска; после перезапуска история пуста, содержимое сохранено.

Отдельное окно Editor prototype заменено редактором в обычных страницах. Ранее созданная страница и её блоки сохранены и открываются через боковую панель. Web-прототип остаётся историческим техническим материалом.

## Приёмка

1. Проверить каталог DAW, Notes и PROG. Создать обычную страницу, добавить все пять типов блоков. Ввести кириллицу и несколько строк.
2. Задать имена, поменять тип блока; проверить сохранность текста. Для ссылки указать URL и открыть её кнопкой.
3. Переместить блоки вверх/вниз. Удалить блок → Отмена → Повтор. Проверить порядок и содержимое.
4. Изменить текст/имя/отметку/URL, проверить Отмена и Повтор кнопками и клавишами. В чек-листе смена отметки не должна менять статусы задач DAW.
5. Ввести текст и сразу переключиться на другую страницу, затем DAW и обратно. Последний ввод сохранён. У двух страниц своя история; отмена одной не меняет другую или DAW Notes.
6. Ввести текст и сразу закрыть окно; открыть приложение. Имена, типы, порядок, URL и чек-лист сохранены. Отмена после перезапуска недоступна.
7. Архивировать страницу и восстановить: все блоки возвращаются. Открыть прежнюю Editor prototype, если она существует: блоки доступны в основном редакторе.
8. Проверить переключение из DAW во время ввода Notes и обратное открытие песни через Все задачи.

## Технические границы

Workspace schema 1 / catalog schema 2 сохранены. В блоке добавлено необязательное строковое поле name; старые документы без name читаются с пустым именем. Новая миграция не требуется.

BlockEditor не знает о владельце документа и файле: получает callbacks чтения/записи блока. BlockEditorSession хранит историю только массива блоков. На обычной странице запись проходит через replacePageBlocks и WorkspaceController, с проверкой исходного содержимого и атомарным сохранением. Ошибочная/устаревшая команда не заменяет живую модель; черновик не исчезает.

Редактор готов к повторному использованию для описания задачи. Реальные общие задачи и подробные страницы задач появляются в 0.1h; интеграция песенных страниц — 0.1i. В 0.1g они не объявлены реализованными.

BlockEditorTests проверяет все типы, Unicode, имена/ID/порядок, удаление/отмену/повтор, независимые истории, сохранение при переключении, отказ записи, конфликт содержимого/файла, архив и обратную совместимость. Все прежние пять тестовых наборов продолжают выполняться.
