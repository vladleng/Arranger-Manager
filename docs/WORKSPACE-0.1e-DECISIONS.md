# 0.1e — модель, хранилище и UI

Дата: 2026-10-02. Этап 1: #37. Реализация от принятой 0.1d в main.
Статус: кандидат на Windows CI и пользовательскую приёмку; 0.1e не принята.

## Хранилище

| Критерий | Версионированный JSON | SQLite |
| --- | --- | --- |
| Миграция нынешнего каталога | Прямое сохранение модели каталога, без изменения Notes keys | Нужны таблицы, транзакции, SQL-миграция и адаптер |
| Маленькое локальное пространство | Полная запись документа приемлема; объём зависит от данных | Точечные обновления и запросы |
| Проверка и переносимость | Один читаемый документ с версией и ID | Экспорт и инструменты просмотра базы |
| Сохранение | Временный файл в той же папке, flush, проверка прочитанного текста, replacement; предыдущая версия в backup | Транзакции, журнал/WAL, системная устойчивость SQLite |
| Большие объёмы аналитики | Полные записи станут дорогими | Индексы и выборки подходят лучше |
| Цена текущего перехода | Без новой зависимости, сохраняется интерфейс каталога | Дополнительная зависимость и слой запросов |

**Решение для 0.1e–0.2:** отдельный документ workspace schema 1; UI-настройки остаются в ApplicationProperties. Сохраняется единый каталог в документе, без второй базы задач. Это транзакция замены всего документа для одного экземпляра приложения, а не обещание всех гарантий СУБД при отключении питания. На этапе аналитики заново оценить SQLite и фоновое хранение по реальным объёмам.

Реализация: WorkspaceModel.h / WorkspaceStore.h. JUCE TemporaryFile создаёт временный файл рядом с целевым и заменяет его после закрытия потока. Перед заменой сохраняется предыдущий валидный документ в .backup. Сбой загрузки/валидации не запускает пустое пространство поверх старого файла. Изменение файла извне блокирует сохранение до перезапуска. Проверка не является межпроцессной блокировкой для других программ; desktop допускает один свой экземпляр.

Источники для технического решения:
- https://docs.juce.com/master/classjuce_1_1TemporaryFile.html
- https://www.sqlite.org/atomiccommit.html

## Модель и миграция

- Workspace: ID, имя, timezone (Asia/Krasnoyarsk), schemaVersion 1 и revision.
- Catalog schema 2: прежние поля плюс UUID песни и UUID её страницы. Путь .song — атрибут записи. Модель содержит relinkSong(id, path); пользовательский выбор перемещённого файла относится к 0.1i.
- Page: ID, parentPageId, title, kind, archivedAt; порядок задаётся массивом.
- Block: ID, type, text, url, checked; порядок задаётся массивом.
- Папка DAW имеет страницу с существующим ID папки; песенная страница вложена в неё.
- Задачи и чек-поинты остаются **единственными записями** внутри каталога. Владелец задачи — pageId её песни; старые ID и правила PROG сохранены. Общие задачи и команды для них — 0.1h.
- Первый запуск переносит songCatalog v1. Сначала записывается точная резервная копия исходного JSON .legacy-v1.json; исходный ключ настроек не изменяется.
- Повторный запуск читает workspace, даже если старые настройки отличаются; миграция не повторяется.
- Некорректные/дублирующиеся данные, неизвестная схема и потеря записей при разборе блокируют миграцию. Формат ошибки сохраняет источник для диагностики.
- Удаление записи песни сохраняет поведение 0.1d; связанные DAW-страницы удаляются. Архивирование и восстановление отдельных страниц появятся в 0.1f/0.1h.

## Сравнение UI на прототипах

Два небольших прототипа с пятью типами блоков, порядком и undo/redo:
- Native: Workspace → Editor prototype, WorkspacePrototype.h. Отдельная обычная страница сохраняется в текущем workspace.
- Web: prototypes/editor-web.html. Самостоятельная тестовая страница, хранит только вымышленный пример в localStorage браузера; не подключена к рабочим данным.

| Сценарий | JUCE-прототип | Отдельный web UI |
| --- | --- | --- |
| Текст, заголовок, список | Нативные TextEditor, размеры шрифта и тип блока | textarea и CSS |
| Чек-лист и ссылка | ToggleButton и отдельное поле URL | checkbox и input URL |
| Порядок и отмена | Перестановка блоков, история в памяти | DOM rendering, история в памяти |
| Хранение | Прямые вызовы текущего WorkspaceStore | Для production нужен IPC/bridge с общими командами |
| Desktop и Hub | Существующий C++ стек без нового runtime | Нужно отдельно решить desktop shell и взаимодействие с DAW |
| Продвинутый rich text | Потребует дополнительной реализации | Браузерные библиотеки редакторов предлагают более широкий выбор |

**Решение:** сохранить JUCE для этапа 1 / 0.2 и вынести модель/хранилище из UI. Для заданных пяти простых типов блоков прототип даёт необходимые контролы; переход к отдельному UI пока добавляет shell/bridge и вторую сборку. Web-прототип оставлен для сравнения пользователем. Это архитектурный выбор по реализованным контрольным сценариям и коду; измерения производительности и визуальная пользовательская оценка ещё не проведены. Не объявлять полноценный редактор 0.1g готовым.

Прототип специально ограничен: один текстовый блок на строку, список как текст с переносами; ссылка хранится как текст/URL и не открывается автоматически. История отмены живёт в памяти окна. Нет форматирования внутри строки, slash-команд и базы произвольных свойств. Эти возможности не входят в 0.1e.
